# ระบบบริหารงบประมาณ (Budget Allocation)

เว็บแอปบริหารงบประมาณงาน A / B / C ทำงานบน **Google Apps Script + Google Sheets**
มีการจำกัดสิทธิ์ผู้ดูแล/ผู้ดูรายงบ, บันทึก log ทุกการเปลี่ยนแปลงพร้อมไฟล์แนบ และแยกยอด "การจอง" กับ "เบิกใช้แล้ว"

---

## 1. สถาปัตยกรรม

```
┌──────────────── เบราว์เซอร์ (Single Page App) ────────────────┐
│  Index.html · Styles.html · JsCore · JsViews · JsForms        │
│  ผู้ดู → หน้า view อ่านอย่างเดียว                                │
│  ผู้ดูแล → drawer ฟอร์มกำหนดงบ / รายการ / สิทธิ์                  │
└───────────────────────────┬───────────────────────────────────┘
                            │ google.script.run → rpc(action, payload)
┌───────────────────────────▼───────────────────────────────────┐
│  Apps Script (หลังบ้าน)                                        │
│  Api.gs        จุดรับคำสั่งเดียว + จัดการ error                   │
│  Auth.gs       ระบุตัวตน + ตรวจสิทธิ์รายงบ                        │
│  Budgets.gs    วงเงิน / จำนวนที่ใช้ได้ / คำนวณยอด                 │
│  Transactions  การจอง + เบิกใช้แล้ว + แก้ไข/ยกเลิก                │
│  Audit.gs      log กลาง (append-only)                          │
│  Attachments   อัปโหลด/ดาวน์โหลดไฟล์ผ่าน Drive                  │
│  Sheets.gs     ชั้นอ่าน-เขียน Sheet + LockService               │
└───────────────────────────┬───────────────────────────────────┘
                            │
        ┌───────────────────▼────────────────────┐
        │ Google Sheets (ฐานข้อมูล 8 ตาราง)        │
        │ Google Drive (โฟลเดอร์ไฟล์แนบต่องบ)       │
        └────────────────────────────────────────┘
```

**ทำไมใช้ Apps Script ไม่ใช่ AppSheet:** โจทย์ต้องการ UI ที่ควบคุมได้เอง (dashboard, กราฟ, drawer, ธีมสว่าง/มืด) และ business rule ที่ซับซ้อน เช่น การตัดยอดจองเมื่อเบิก ซึ่ง AppSheet ทำได้จำกัด ถ้ายังต้องการฟอร์มบนมือถือแบบ AppSheet สามารถต่อ AppSheet เข้ากับ Sheet ชุดเดียวกันได้ภายหลัง เพราะข้อมูลอยู่ที่ Sheet เหมือนกัน

## 2. โครงสร้างข้อมูล (8 ชีต)

| ชีต | หน้าที่ | แก้ไขได้ |
|---|---|---|
| `Budgets` | ทะเบียนงบ A/B/C — รหัส, ชื่อ, ปีงบ, **วงเงินงบประมาณ**, **จำนวนที่ใช้ได้**, สถานะ | ใช่ (ผ่านแอป) |
| `Permissions` | สิทธิ์รายงบ: `budget_id` + `email` + `role` (ADMIN/VIEWER) | ใช่ |
| `Transactions` | รายการใช้งบ: `RESERVE` (การจอง) / `DISBURSE` (เบิกใช้แล้ว) | ใช่ |
| `BudgetChanges` | ประวัติการกำหนด/ปรับ วงเงิน และจำนวนที่ใช้ได้ | **ไม่ (append-only)** |
| `AuditLog` | log กลางทุก action พร้อม before/after JSON + เหตุผล + ไฟล์แนบ | **ไม่ (append-only)** |
| `Attachments` | ทะเบียนไฟล์แนบ → ผูกกับงบ / รายการ / การเปลี่ยนวงเงิน | **ไม่** |
| `Users` | ผู้ใช้ระบบ + สิทธิ์ระดับระบบ (SUPER_ADMIN) | ใช่ |
| `Config` | ชื่อระบบ, ชื่อหน่วยงาน, เกณฑ์เตือนสี (80% / 95%) | ใช่ (แก้ในชีตตรง ๆ ได้) |

ยอดคงเหลือ **ไม่เก็บซ้ำในชีต** แต่คำนวณสดทุกครั้งเพื่อกันข้อมูลเพี้ยน:

```
reservedOutstanding = Σ (amount − settled_amount)   ของการจองที่ยัง ACTIVE
disbursed           = Σ amount                      ของการเบิกที่ยัง ACTIVE
committed           = reservedOutstanding + disbursed
availableToSpend    = usable_amount − committed      ← ยอดที่ยังใช้ได้จริง
unreleased          = budget_amount − usable_amount  ← วงเงินที่ยังไม่ปล่อยให้ใช้
```

**การเบิกที่อ้างอิงการจอง** จะเพิ่ม `settled_amount` ของรายการจองนั้น จึงไม่นับวงเงินซ้ำ
เมื่อเบิกครบ รายการจองจะเปลี่ยนสถานะเป็น `SETTLED` อัตโนมัติ

## 3. สิทธิ์การใช้งาน

### ระดับระบบ (เมนูผู้ใช้)

| บทบาท | ความสามารถ |
|---|---|
| **ผู้ดูแลระบบ** | ทุกอย่าง: สร้างงบ, จัดการผู้ใช้, ย้ายรายการ, ประวัติทั้งหมด, ภาพรวม |
| **ผู้บริหาร** | ดูทุกโครงการ + ภาพรวม — อ่านอย่างเดียว ไม่ต้องมีสิทธิ์รายงบ |
| **ผู้ใช้งาน** | เห็นเฉพาะงบที่ถูกกำหนดในฟอร์มสร้าง/แก้ไขงบ |

### ระดับรายงบ (ในฟอร์มสร้าง/แก้ไขงบ)

| บทบาท | ความสามารถ |
|---|---|
| **ผู้รับผิดชอบ** | แก้ข้อมูลงบ, ปรับวงเงิน, รายการใช้งบ, ดูประวัติ |
| **ผู้จัดการรายการ** | เพิ่ม/แก้รายการจอง–เบิก, ดูประวัติ |
| **ผู้ดู** | ดู dashboard/รายการ — ไม่เห็นประวัติ |

`code` = หมวด A–Z (**ซ้ำได้**หลายโครงการ) · สถานะ: **New** → **Process** (อัตโนมัติเมื่อมีรายการแรก) → **Close**  
ปีงบประมาณเป็นข้อความอิสระ (เช่น `หลังปี 2026`)

การตรวจสิทธิ์ทำที่ **ฝั่งเซิร์ฟเวอร์ทุกครั้ง**

## 4. กฎที่ระบบบังคับ

- ปรับ **จำนวนที่ใช้ได้** เกิน **วงเงินงบประมาณ** → ปฏิเสธ
- ลด **จำนวนที่ใช้ได้** ต่ำกว่ายอดที่ผูกพันแล้ว → ปฏิเสธ พร้อมบอกยอดที่ผูกพัน
- ลด **วงเงิน** ต่ำกว่าจำนวนที่ใช้ได้ → ปฏิเสธ (ให้ลดจำนวนที่ใช้ได้ก่อน)
- บันทึกจอง/เบิกเกินวงเงินคงเหลือ → ปฏิเสธ พร้อมแสดงที่มาของยอด
- เบิกอ้างอิงการจอง เกินยอดจองคงค้าง → ปฏิเสธ
- ยกเลิกการจองที่มีการเบิกแล้ว → ปฏิเสธ (ให้ยกเลิกการเบิกก่อน)
- **การเปลี่ยนวงเงิน / แก้ไข / ยกเลิก ต้องระบุเหตุผลอย่างน้อย 5 ตัวอักษร**
- งบสถานะ `CLOSED` / `Close` → อ่านได้เท่านั้น
- ย้ายรายการจอง+เบิกทั้งชุดได้เฉพาะผู้ดูแลระบบ
- ทุกการเขียนใช้ `LockService` กันข้อมูลชนกันเมื่อมีผู้ใช้พร้อมกัน
- ไม่มีการลบข้อมูลจริง — ใช้สถานะ `CANCELLED` / `REVOKED` เพื่อคงร่องรอยตรวจสอบ

## 6. การติดตั้ง

### วิธี A — วางไฟล์ในตัวแก้ไข Apps Script (ไม่ต้องลงเครื่องมือ)

1. สร้าง Google Sheet ใหม่ → เมนู **ส่วนขยาย › Apps Script**
2. ในตัวแก้ไข กด ⚙️ **Project Settings** → ติ๊ก *Show "appsscript.json" manifest file*
   แล้วกลับมาที่ **< >  Editor** (ไอคอนวงเล็บปีกกาในแถบซ้ายสุด)

3. **คัดลอกเนื้อหาไฟล์ทั้ง 16 ไฟล์เข้าไป** — ดูรายละเอียดทีละขั้นใน
   [ภาคผนวก: ขั้นตอนข้อ 3 แบบละเอียด](#ภาคผนวก-ขั้นตอนข้อ-3-แบบละเอียด) ด้านล่าง
   สรุปสั้น ๆ: ไฟล์ `Code.gs` กับ `appsscript.json` มีอยู่แล้วให้ทับเนื้อหาเดิม
   ส่วนอีก 14 ไฟล์กด **+ › Script** (สำหรับ `.gs`) หรือ **+ › HTML** (สำหรับ `.html`)
   โดยพิมพ์ชื่อไฟล์ **ไม่ต้องใส่นามสกุล**

4. เลือกฟังก์ชัน `setup` → **Run** → อนุญาตสิทธิ์ (ครั้งเดียว)
   สร้างชีตทั้ง 8, โฟลเดอร์ไฟล์แนบใน Drive และตั้งคุณเป็นผู้ดูแลระบบคนแรก
5. (ไม่บังคับ) เลือกฟังก์ชัน `seedDemoData` → **Run** เพื่อสร้างงบตัวอย่าง A / B / C
   (ต้องคลิกไฟล์ `Setup.gs` ในแถบซ้ายก่อน ช่องเลือกฟังก์ชันจะแสดงเฉพาะฟังก์ชันของไฟล์ที่เปิดอยู่)
6. **Deploy › New deployment** → กดเฟือง ⚙️ ข้าง *Select type* → **Web app**
   - Execute as: **Me (อีเมลของคุณ)**
   - Who has access: **Anyone within [องค์กรของคุณ]**
7. คัดลอก **Web app URL** (ลงท้าย `/exec`) → เปิดใช้งานได้ทันที
   ดู URL ย้อนหลังได้ที่ **Deploy › Manage deployments**

### วิธี B — ใช้ clasp

```bash
npm i -g @google/clasp
clasp login
clasp create --type sheets --title "ระบบบริหารงบประมาณ" --rootDir .
clasp push
clasp open
# แล้วรัน setup() และ Deploy ตามขั้นตอนที่ 4–7 ข้างบน
```

### Script Properties ที่ใช้ได้

| คีย์ | ค่า |
|---|---|
| `SPREADSHEET_ID` | ตั้งอัตโนมัติโดย `setup()` — เปลี่ยนได้ถ้าต้องการชี้ไปชีตอื่น |
| `ATTACHMENT_FOLDER_ID` | โฟลเดอร์ Drive เก็บไฟล์แนบ |
| `SUPER_ADMINS` | อีเมลผู้ดูแลระบบ คั่นด้วย `,` (ใช้กู้สิทธิ์เมื่อ lock ตัวเองออก) |
| `DEV_IMPERSONATE_EMAIL` | สวมรอยอีเมลตอนทดสอบในตัวแก้ไข **ให้ลบทิ้งก่อนใช้งานจริง** |

> **หมายเหตุเรื่องการระบุตัวตนและความปลอดภัย (สำคัญ):**
> ระบบนี้ออกแบบให้ deploy แบบ *Execute as: **Me*** + *Who has access: **Anyone within องค์กร***
> ซึ่งต้องใช้บัญชี **Google Workspace** (อีเมลโดเมนองค์กร ไม่ใช่ `@gmail.com`)
>
> - โค้ดจะทำงานด้วยสิทธิ์ของเจ้าของสคริปต์ ผู้ใช้จึง **ไม่ต้องถูกแชร์ Google Sheet เลย**
>   เปิดชีตตรง ๆ ไม่ได้ อ่าน/แก้ข้อมูลได้เฉพาะผ่านเว็บแอปที่ตรวจสิทธิ์แล้ว
> - `Session.getActiveUser().getEmail()` คืนอีเมลจริงได้เพราะผู้ใช้อยู่โดเมนเดียวกับเจ้าของสคริปต์
> - ถ้าระบุตัวตนไม่ได้ ระบบจะ **โยน error ทิ้ง ไม่ fallback** ไปเป็นเจ้าของสคริปต์ (กัน privilege escalation)
>
> ห้ามเลือก *Execute as: User accessing the web app* กับระบบนี้ เพราะโค้ดจะเขียนชีตด้วยสิทธิ์ของผู้ใช้
> ทำให้ต้องแชร์ชีตแบบ **Editor** ให้ทุกคน ผู้ใช้ระดับ *ผู้ดู* จะเปิดชีตอ่าน/แก้ข้อมูลทุกงบได้ตรง ๆ
> เลี่ยงระบบสิทธิ์ทั้งหมด

## 7. ลำดับการใช้งานจริง

**ผู้ดูแลระบบ**
1. `หลังบ้าน › จัดการงบประมาณ` → **สร้างงบประมาณ** (รหัส A, ชื่อ, วงเงิน, จำนวนที่ใช้ได้, เหตุผล, แนบเอกสารอนุมัติ)
2. เปิดงบ → แท็บ **สิทธิ์การเข้าถึง** → เพิ่มผู้ดูแลงบและผู้ดู
3. `หลังบ้าน › ผู้ใช้และสิทธิ์` → ดูตารางสิทธิ์รายงบทั้งหมดในหน้าเดียว

**ผู้ดูแลงบ**
1. **฿ ปรับวงเงิน** → สลับระหว่าง *วงเงินงบประมาณ* / *จำนวนที่ใช้ได้* ระบบแสดงผลกระทบก่อนบันทึก
2. **+ บันทึกการจอง** → กันวงเงินไว้ล่วงหน้า
3. **+ บันทึกการเบิก** → เลือก "เบิกจากรายการจอง" เพื่อตัดยอดจอง หรือเบิกตรงจากวงเงินคงเหลือ
4. **แก้ไข / ยกเลิก** → ต้องใส่เหตุผล แนบไฟล์ได้ ระบบเก็บค่าก่อน–หลัง

**ผู้ดู**
- ภาพรวมงบประมาณ → การ์ดทุกงบ + กราฟรายเดือน + สัดส่วนการใช้
- เปิดงบ → 5 แท็บ: สรุป / รายการใช้งบ / ประวัติวงเงิน / สิทธิ์ / บันทึกการตรวจสอบ
- `รายการใช้งบ` → ค้นหาข้ามงบ กรองตามประเภท สถานะ ช่วงวันที่
- `ประวัติการเปลี่ยนแปลง` → ไทม์ไลน์ audit พร้อม diff ก่อน–หลัง และไฟล์แนบ

## 8. ข้อจำกัดที่ควรรู้

- Google Sheets เหมาะกับข้อมูลระดับหมื่นแถว ถ้ารายการเกิน ~50,000 แถว ควรย้ายไปฐานข้อมูลจริง

- ยังไม่มีระบบอนุมัติหลายขั้น (maker–checker) หากต้องการ เพิ่มสถานะ `PENDING_APPROVAL` ใน `Transactions` และปุ่มอนุมัติสำหรับผู้ดูแลระบบ

## ภาคผนวก: ขั้นตอนข้อ 3 แบบละเอียด

สำหรับผู้ที่ไม่ได้เขียนโปรแกรม — งานทั้งหมดคือ **"คัดลอกข้อความจากไฟล์ในเครื่อง ไปวางในหน้าเว็บ Apps Script"**
ทำซ้ำ 16 รอบ ใช้เวลาประมาณ 20–30 นาที ทำครั้งเดียวจบ

### สิ่งที่เห็นบนหน้าจอ Apps Script

แถบซ้ายมือของตัวแก้ไขคือรายการไฟล์ (Files) ตอนนี้จะมีอยู่ 2 ไฟล์:

```
Files          +      ← ปุ่ม + นี้คือปุ่มสร้างไฟล์ใหม่
  Code.gs
  appsscript.json
```

เป้าหมายคือทำให้รายการนี้มีครบ 16 ไฟล์ตามตารางด้านล่าง

### กฎ 4 ข้อที่ต้องจำ (พลาดตรงนี้บ่อยที่สุด)

1. **พิมพ์ชื่อไฟล์โดยไม่ต้องใส่นามสกุล** — พิมพ์ `Schema` ไม่ใช่ `Schema.gs`
   ระบบจะเติม `.gs` หรือ `.html` ให้เองตามชนิดที่เลือก
2. **ตัวพิมพ์เล็ก-ใหญ่ต้องตรงเป๊ะ** — `JsCore` ใช้ได้ แต่ `jscore` หรือ `JSCore` จะพัง
3. **ไฟล์ HTML ต้องลบข้อความตั้งต้นออกก่อน** — เมื่อสร้างไฟล์ HTML ใหม่
   Google จะใส่โครงร่างเปล่ามาให้ประมาณ 5 บรรทัด ต้องกด `Ctrl+A` แล้ว `Delete`
   ให้ว่างสนิทก่อนวางของเรา
4. **คัดลอกทั้งไฟล์เสมอ** — รวมบรรทัดคอมเมนต์และบรรทัดว่างด้านบน-ล่าง

### วิธีคัดลอกเนื้อหาจากไฟล์ในเครื่อง

ไฟล์ทั้งหมดอยู่ที่ `C:\Users\PC-DIAG\Downloads\Budget allocation`

- **ถ้าเปิด Cursor อยู่แล้ว** (แนะนำ): คลิกชื่อไฟล์ในแถบซ้าย → คลิกในพื้นที่โค้ด →
  `Ctrl+A` (เลือกทั้งหมด) → `Ctrl+C` (คัดลอก)
- **หรือใช้ Notepad**: คลิกขวาที่ไฟล์ → *Open with* → *Notepad* → `Ctrl+A` → `Ctrl+C`
  (ถ้าไม่เห็นไฟล์ `.gs` ให้เลือก *All files* ในช่องชนิดไฟล์)

### ขั้นที่ 3.1 — ทับไฟล์ 2 ไฟล์ที่มีอยู่แล้ว

ไฟล์สองไฟล์นี้ **ห้ามสร้างใหม่** ให้ทับของเดิม มิฉะนั้นจะได้ชื่อซ้ำเป็น `Code1.gs`

| ไฟล์ใน Apps Script | ทำอะไร |
|---|---|
| `Code.gs` | คลิกที่ไฟล์ → คลิกในพื้นที่โค้ด → `Ctrl+A` → `Delete` → วางเนื้อหาจาก `Code.gs` ในเครื่อง |
| `appsscript.json` | คลิกที่ไฟล์ → `Ctrl+A` → `Delete` → วางเนื้อหาจาก `appsscript.json` ในเครื่อง |

กด `Ctrl+S` เพื่อบันทึก (หรือไอคอนรูปแผ่นดิสก์ด้านบน)

> ถ้าไม่เห็น `appsscript.json` ในรายการ แปลว่ายังไม่ได้ติ๊กในข้อ 2 — กลับไปที่
> ⚙️ **Project Settings** แล้วติ๊ก *Show "appsscript.json" manifest file* ใหม่

3. พิมพ์ชื่อไฟล์จากตาราง (ไม่ใส่ `.gs`) แล้วกด `Enter`
4. Google จะใส่ฟังก์ชันตัวอย่าง `function myFunction() {}` มาให้ →
   `Ctrl+A` → `Delete` → วางเนื้อหาไฟล์จริง → `Ctrl+S`

### ขั้นที่ 3.4 — ตรวจก่อนไปข้อ 4

รายการไฟล์ต้องหน้าตาแบบนี้พอดี (เรียงลำดับไม่สำคัญ):

```
Api.gs            Index.html
Attachments.gs    Styles.html
Audit.gs          JsCore.html
Auth.gs           JsViews.html
Budgets.gs        JsForms.html
Code.gs
Schema.gs         appsscript.json
Setup.gs
Sheets.gs
Transactions.gs
```

จุดที่ควรเช็ค:
- ไม่มีไฟล์ชื่อซ้ำแบบ `Code1.gs`, `Schema1.gs` (ถ้ามี = สร้างเกิน ให้ลบทิ้งด้วยจุดสามจุดข้างชื่อไฟล์ › *Delete*)
- ไม่มีไฟล์ไหนที่เนื้อหาว่างเปล่า
- ไฟล์ HTML ทั้ง 5 ต้องไม่มี `<!DOCTYPE html>` ซ้ำสองชุด (ถ้ามี = ลืมลบโครงร่างเดิม
  — `Index.html` ของเรามี `<!DOCTYPE html>` อยู่แล้ว 1 ชุดซึ่งถูกต้อง
  ส่วน `Styles`, `JsCore`, `JsViews`, `JsForms` ต้องขึ้นต้นด้วย `<style>` หรือ `<script>` เท่านั้น)

หากผ่านครบแล้วให้ไปข้อ 4 (`Run` ฟังก์ชัน `setup`) ได้เลย

### ถ้าติดปัญหาตอนข้อ 4

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| ไม่เห็นชื่อฟังก์ชัน `setup` ในช่องเลือก | ไฟล์ `Setup.gs` ยังไม่ถูกวาง หรือชื่อไฟล์สะกดผิด |
| `ReferenceError: CFG is not defined` | ไฟล์ `Schema.gs` ว่างหรือยังไม่ได้สร้าง |
| `ReferenceError: getSheet_ is not defined` | ไฟล์ `Sheets.gs` ว่างหรือยังไม่ได้สร้าง |
| หน้าเว็บขึ้นว่างเปล่าหลัง Deploy | ชื่อไฟล์ HTML สะกดผิด (ต้องเป็น `Index`, `Styles`, `JsCore`, `JsViews`, `JsForms` เป๊ะ ๆ) |
| ขึ้นหน้าขออนุญาตแล้วเตือน "Google hasn't verified this app" | ปกติสำหรับสคริปต์ที่เขียนเอง → กด *Advanced* → *Go to (ชื่อโปรเจกต์) (unsafe)* → *Allow* |
